# Вступительный тест: доска сообщений на Go

HTTP-сервер на Go в шесть этапов. Спецификация ниже, тесты лежат в `tests/`,
фронтенд готов - откроете в браузере и увидите, что уже работает.

Рассчитано на 2–4 часа, распределите их как удобно до дедлайна.

## Правила

- Язык - Go. Библиотеки любые, стандартной хватает: `net/http` плюс маршруты с
  методом и параметром (`mux.HandleFunc("DELETE /messages/{id}", ...)`).
- `tests/` и `frontend/` не трогайте: проверяем нетронутыми тестами, правки там
  ничего не дадут.
- Сдаёте git-репозиторий, ссылкой или архивом. Коммиты по этапам читать удобнее.
- Готово, когда `go test ./tests/ -v` зелёный.

## Старт

1. Поставьте Go 1.25 или новее: https://go.dev/dl/ (`go.mod` требует `go 1.25`).
2. `go run ./cmd/server` - сервер поднимается на порту из `PORT`, по умолчанию 8080.
3. `go test ./tests/ -v` - шесть падающих этапов. Закрывайте по одному.
4. Откройте http://localhost:8080/ - панель работает сразу, там живой чек-лист.
   Пункты зеленеют по мере того, как вы закрываете этапы.

Порт читайте из переменной окружения `PORT`: тестовый стенд занимает случайный
свободный. Заготовка `cmd/server/main.go` это уже делает, достраивайте её или
выкиньте целиком - лишь бы `go build ./cmd/server` собирал сервер. Если
переписываете заготовку с нуля, не потеряйте раздачу `frontend/`: без неё
панель пропадёт, а `TestStage1_Frontend` покраснеет.

Сообщения храните в памяти. Ни базы, ни файлов: после перезапуска доска пустая,
так и задумано.

Что лежит в комплекте:

```
cmd/server/main.go   заготовка: PORT, раздача frontend/, TODO по этапам
frontend/            панель с чек-листом, эхо-формой и доской - готова
tests/               шесть этапов, стенд собирает и поднимает ваш сервер сам
```

## Этапы

### Этап 1 - Здоровье и фронтенд

| Запрос | Ответ |
|---|---|
| `GET /health` | `200`, тело `ok` |
| `GET /` | `200`, статика из каталога `frontend/` - уже сделано в заготовке |

Раздача `frontend/` идёт в заготовке одной строкой, так что писать нужно только
`/health`.

```
$ curl localhost:8080/health
ok
```

### Этап 2 - Эхо, обычный текст

`POST /echo` отвечает `200` и телом запроса, байт в байт.

```
$ curl -X POST localhost:8080/echo -d 'hello'
hello
```

### Этап 3 - Эхо, JSON

Пришёл `Content-Type: application/json` - разберите `{"message": "<строка>"}` и
верните обратно JSON-ом, с `Content-Type: application/json` в ответе. Сломанный
JSON - `400`.

```
$ curl -X POST localhost:8080/echo -H 'Content-Type: application/json' -d '{"message": "hi"}'
{"message":"hi"}
```

### Этап 4 - Создание сообщений

`POST /messages` принимает `{"message": "<непустая строка>"}`, кладёт его в память
и отвечает `201` с сохранённым сообщением:

```json
{"id": 1, "message": "hi", "created_at": "2026-06-10T12:00:00Z"}
```

- `id` - целое, своё у каждого сообщения; возрастающего счётчика хватит
- `created_at` - метка времени в формате RFC 3339
- сломанный JSON, отсутствующий `message`, пустая строка - `400`

### Этап 5 - Список

`GET /messages` возвращает `200` и JSON-массив всех сообщений, новые сверху:
последнее созданное на индексе 0. По строке с временем не сортируйте.

Пустая доска - `[]`, `null` тесты не примут.

### Этап 6 - Удаление

`DELETE /messages/{id}` удаляет одно сообщение.

| Случай | Ответ |
|---|---|
| Сообщение есть | `204`, пустое тело |
| Такого id нет | `404` |

```
$ curl -X DELETE localhost:8080/messages/1 -i
HTTP/1.1 204 No Content
```

## Что обычно спрашивают

**ИИ-ассистенты, поиск.** Пользуйтесь всем, чем пользуетесь в работе. Дальше шесть
недель опираться на это знание, так что сдавайте то, в чём разобрались сами.

**Конкурентность.** Стенд не грузит сервер параллельно, но `net/http` вызывает
обработчик в отдельной горутине, так что мьютекс на общем хранилище - правильная
привычка.

**Тесты висят на старте.** Стенд ждёт 10 секунд, пока сервер начнёт слушать `PORT`.
Проверьте, что порт берётся из окружения, а не зашит в код.

**Тест зелёный, а код меняли.** Go кэширует прогоны: `go test ./tests/ -v -count=1`
считает заново.

**На доске появляется «проверка этапа».** Панель проверяет этапы 4–6 живьём:
создаёт сообщение, ищет его в списке, удаляет. После прохода этапа 6 оно исчезает.

**Спецификация выглядит неоднозначно.** Смотрите падающий тест, он точнее.
